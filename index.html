⚙️ How It Works

nix-demo uses three ideas together. First, there is a Git patch. Think of a patch as a small, recorded change. Second, there is a Nix overlay. Think of an overlay as a reusable recipe that tells the project how to apply that change. Third, there are three places where the change is used: a development workspace, a test machine, and a Docker image.

A development workspace

A development workspace is the place where a project is prepared and checked. In nix-demo, the workspace receives the same Git change through the overlay. This means the workspace does not need a separate manual edit.

A test machine

A test machine is an automatic check that runs in a clean setting. nix-demo uses the same change there, so the test reflects the real result. This helps catch differences early.

A Docker image

A Docker image is a packaged copy of an environment. nix-demo puts the same change into that package. As a result, the packaged copy and the development workspace stay aligned.

The main benefit is consistency. You patch Git once, and the same change travels to each place. That reduces repeated work and lowers the chance of one setup drifting away from another.
